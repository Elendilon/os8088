# What is in `docs/`, and where a new document goes

**The directory says what a document is.** The filename does not, and that was
the problem this layout fixes: `HANDOFF-REDRAW.md` is a plan with no `PLAN` in
its name, `KERNEL-MEMORY.md` is maintained reference that happened to sit
beside eighty design records, and nothing on the outside of either file told a
reader which it was holding. Ninety-five documents in one flat directory meant
every one of them read as current.

| directory | what is in it | read it as |
|---|---|---|
| `docs/` | how the system works **today** — instructions, contracts, maintained reference | true of the tree you have checked out |
| `docs/plans/` | proposed or half-finished work | a **proposal**; the tree does not do this yet, or does part of it |
| `docs/plans/completed/` | the design record behind something that shipped | **how it got there**, not what it does — SPEC.md is what it does |
| `docs/history/` | superseded, or a record of a moment that has passed | true of **no** tree you can check out |

`docs/INDEX.md` lists every one of them under those four headings and is
generated by `tools/os88index.py`, which takes the classification from the
path. Moving a file is therefore the whole of reclassifying it — there is no
second list to remember.

## Where a new document goes

- Describes what the code does now, or tells someone how to do something →
  **`docs/`**. It has to stay true, and it is expected to change in the same
  commit as the code that makes it false.
- Proposes work, or records work that is part done → **`docs/plans/`**.
  Handoffs are plans: a handoff is a plan addressed to whoever picks it up.
- Its work has landed → move it to **`docs/plans/completed/`**. Do this in the
  commit that lands the work, not later; a finished plan left in `docs/plans/`
  reads as an open commitment.
- Superseded, or answered by something that replaced it, or a report of a bug
  that no longer reproduces → **`docs/history/`**. Nothing here is deleted:
  the reasoning is usually worth more than the conclusion, and a study that
  ruled something out is what stops it being re-derived.

**A REGISTER also lives in `docs/plans/`** — `LAST-DROP-BYTES.md` and
`LAST-DROP-PERF.md` are menus of things the machine could do, each priced,
each deferred indefinitely. They are outstanding forever by design and are
finished only when empty, which nobody is working towards. They are filed as
plans because a row is a proposal, not a description of the tree; do not read
one as a commitment.

**A plan with some waves built and some not stays in `docs/plans/`** — that is
what "half done" means and where a reader should find it. Split it into a
completed record and a remaining plan only when the two halves have stopped
being one argument; when you do, each must name the other in its first lines.

## What does not move

`SPEC.md`, `PERFORMANCE.md` and `REDRAW-SPEC.md` are at the repository root and
stay there. A bare `§` anywhere in this repository means SPEC.md.

## Citing one

Cite a document by its **full path and a section number** —
`docs/plans/completed/TEXT-PLAN.md §4.4`. `tools/checkdocs.py` resolves the
document by its basename, so a citation survives a move between these four
directories, but it checks the section number against the file it names: a
number that is not a heading there fails the build. Every `make` runs it.
