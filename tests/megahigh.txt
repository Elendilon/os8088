# tests/megahigh.txt - the OS88_HIGH / OS88_HIGHMEM exemption registry
# (docs/plans/KERN-MEGA-PLAN.md 14.51, 14.52)
#
# On kern_mega two bits of a package's class byte (+15) are the opt-in to
# extended memory (apps/os88api.inc): OS88_HIGH, the region may be loaded
# above 1MB, and OS88_HIGHMEM, its claims of 64KB or less may be too. The
# owner's rule: "opt in is fine but only with a full tier gate. They need to
# except themselves if they want to not opt in, and they need a damn good
# reason to do so."
#
# ONE LINE PER EXEMPTION: <kind> <package>  # <reason>
#
#   high     the package does not declare OS88_HIGH
#   highmem  it does not declare OS88_HIGHMEM
#
# A reason may run on over indented `#` lines below it. tests/unit/t_megahigh.py
# (full tier) is the gate, and the list turns ONE WAY: a line for a package
# that now declares is a FAILURE.
#
# THE BAR. A reason names a concrete thing in the code that breaks above 1MB -
# paragraph arithmetic on its own CS/DS or on a claim's segment, a far pointer
# kept for real mode, an IRQ vector stamped with its own CS, DMA or a BIOS
# call on a claim, a claim over 64KB stepped by segment arithmetic - with the
# place it is and what would retire the line. "Nobody looked" is not one: if
# you looked and found nothing, the answer is the declaration, after running
# the package on kern_mega (docs/BOCHS.md).
#
# NOT HERE, BY CONSTRUCTION: a parts LOADER (its source invokes OS88_REHOME -
# csload, wdload, scload, dosload, pxstein) is never asked for `high`, and is
# asked for `highmem` only when its own source claims. The gate's docstring
# says why; its program part is a package of its own and is checked as one.

# --- high --------------------------------------------------------------------

high apps/sheet/sheet.asm       # ITS OWN CS STAMPED INTO TWO OVERLAYS: ch_ovbind
    # (apps/os88chartovl.inc) and sh_ovbind (sheet.asm, `mov ax, cs`) write the
    # region's CS into the vector tables the chart and macro modules far-call
    # back through, as real-mode far pointers. The modules ARE parts of
    # SHEET.O88 now (SPEC.md 82.16.12, the sidecars-to-parts PR #289's review
    # flagged), but those tables still carry a real-mode CS, so this is retired
    # when they are reached through a selector kern_mega can patch. Not run on
    # kern_mega.
high apps/realdmg/realdmg.asm     # NOT YET RUN HIGH: since REALDMG-SPEC
    # 16.2.4 the far vectors the core jumps through (S_EVVEC, S_IORVEC,
    # S_IOWVEC, S_MBCVEC) hold the region's CODE selector (`mov ax, cs`) and
    # rw_reloc re-stamps them by rw_csel, so the line's first reason is gone;
    # what is left is that the region above 1MB has never been run - the
    # parts carve, the worker's restart and the log's pins against a region
    # whose selectors do not move. Retired by one MEGATRAP run with OS88_HIGH
    # in the class byte (tests/rdgmega.py's shape) and the declaration.

# --- highmem -----------------------------------------------------------------

highmem apps/sheet/sheet.asm    # FAR-CALLS CODE IN A CLAIM: its two module parts
    # are read into claims and entered with `call far [ch_ovfar]` /
    # `call far [sh_m2far]` at (0, the claim's segment) - os88chartovl.inc's
    # ch_ovneed and sheet.asm's sh_m2need - which OS88_HIGHMEM's contract
    # rules out (apps/os88api.inc). Retired with the `high` line above.
highmem apps/realdmg/realdmg.asm  # PARAGRAPH ARITHMETIC ON ITS CLAIMS: cartridge
    # RAM banks at S_RAMSEG + bank x 200h (rdg_rambank, rdgsys.inc), the bank
    # cache's slots at rw_slotseg + slot x 400h (rwbank.inc), the recompiler's
    # block table at its cache's segment + 1000h and its part past the table
    # (rw_jitsegs, rw_jitget), and the cache and part entered as CODE through
    # OSAPI_MEM_CODESEL's identity alias, which a lone data selector above
    # 1MB has none of. (Its link patches no longer write through CS -
    # REALDMG-SPEC 16.2.4 - and kern_mega's arm keeps the cartridge itself
    # above 1MB in place, 10.3.1.) Retired by addressing each claim at its own
    # selector and a code twin for the cache segments.

highmem apps/pixel/pixel.asm     # PARAGRAPH ARITHMETIC ON EVERY CLAIM IT HOLDS
    # (KERN-MEGA-PLAN 14.40 item 4): the master is addressed as MSEG +
    # (offset >> 7 << 3) at nine sites, the work claim is cut into
    # sub-buffers by paragraph offsets (PX_WGRID, px_wo_*) handed to the parts
    # as PXK_RSEG/PXK_DSEG, the PNG scanlines sit at PXK_DSEG + PZ_WPARA, the
    # JPEG progressive store at the scratch + JV_SBASE, the histogram tail past
    # the master and the animation's backup inside its claim. Right on the
    # identity map, meaningless on an LDT selector over exactly the KB asked.
    # Retired by 14.12's "flat arm" at every site (seg = claim, offset = the
    # absolute address when `test dl, 4`) - a rewrite of PiXEL's addressing.
    # OS88_HIGH it already says.
