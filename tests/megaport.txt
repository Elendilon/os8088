# tests/megaport.txt - MartyPC soak rows PORTED to kern_mega.
#
# Each line registers `mega-<name>` (tests/suite.py's _mega_ports): the SAME
# script as soak row <name>, run with OS88_MEGA=1, which makes
# os88marty.launch() answer tools/os88bochsmarty.py - Bochs on build/mega.img
# with build/megaapps.img in B: (docs/BOCHS.md, "Rows ported from MartyPC").
#
#     name [secs=N] [timeout=N] [@VAR=VAL ...] [+arg ...] [-arg ...] [-flag=]   # why
#
# `@VAR=VAL` puts VAR in the row's environment - `@OS88_BOCHS_MEGS=1` boots a
# 1MB machine, which has no pool above 1MB, so every claim is conventional and
# SELECTOR-named: the heap rows' scenarios are kern_big's arena there, and the
# compactor they drive is kern_mega's (KERN-MEGA-MEMORY-PLAN MC7.4).
#
# `secs` is MEASURED on the port (Bochs runs the guest at real time, so a row
# that is guest-heavy costs more than its MartyPC figure); without one it is
# twice the base row's. A row is listed here only once it PASSES on kern_mega
# - and was seen to go red when the thing it checks was broken - or once its
# failure is a kern_mega defect that is fixed in the same change.
