os8088 INPUT DEBUG DISK
=======================

This disk boots os8088 and opens Input Check by itself. It is for when the
keyboard or the mouse does not work the way it should on your machine - a
PS/2 keyboard that is "sometimes not recognised", a mouse that is not found,
or one mouse that works where another does not.

The kernel and drivers are the SAME as on the system disk. Nothing is a
special build: Input Check reads what the system already recorded at boot,
and looks at the keyboard controller itself.

WHAT HAPPENS WHEN IT BOOTS
--------------------------
1. Input Check opens and asks you to PRESS SOME KEYS for about 20 seconds:
   letters, Num Lock, Caps Lock. If the keyboard is dead, that is fine -
   leave it, and the report says so.
2. It saves a report to this disk: INPUT01.TXT on the first boot, INPUT02.TXT
   on the next, and so on. Nothing is overwritten.
3. It checks the keyboard controller (the keyboard switches off for about a
   third of a second) and, if no PS/2 mouse was found at boot, runs the PS/2
   mouse probe again.
4. It asks for keys AGAIN for about 10 seconds, then saves the same file
   once more, complete. The window says "Done".

Q and Esc do nothing while it runs, so pressing keys cannot close it.

WHAT TO SEND US
---------------
Boot this disk SEVERAL times - ideally until you have caught at least one
boot where the keyboard works and one where it does not. Each boot writes
its own file. Then send:

  - every INPUT??.TXT from this disk (it is a normal FAT floppy: copy them
    off on any PC), and
  - for each boot, whether the keyboard worked, and which mouse (if any)
    was plugged in where.

A photograph of the screen at "Done" helps too, especially if a file did
not save.

If the keyboard is dead on a boot and you have a SERIAL mouse, the window
still works with it after the run: Save Report (S, or the button) writes
another copy anywhere you choose.

Keys after the run: K checks the keyboard controller again, P probes the
PS/2 mouse port, R refreshes, S saves, C copies, Q quits.

OTHER CHECKS ON THIS DISK
-------------------------
The APPS folder also holds the other diagnostics, to start by hand:
SNDDIAG.O88 (Sound Debug) and REDLINE.O88 (the benchmark, whose Inspect
page lists the machine's hardware). Sound Debug here can only say that the
sound driver kept no record: for a sound report, boot the sound debug disk.
